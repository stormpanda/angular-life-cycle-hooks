Key Points About ngOnInit

  • When it runs: Once after the first ngOnChanges (if any inputs exist)
  • Perfect for: HTTP requests, subscriptions, complex object initialization
  • Why not constructor: Component inputs aren't available yet in constructor
  • Timing: Component is fully initialized but view isn't rendered yet
  • Best practices: Keep constructor light, do heavy lifting in ngOnInit
  • Cleanup: Remember to unsubscribe in ngOnDestroy to prevent memory leaks
